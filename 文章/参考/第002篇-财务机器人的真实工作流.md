# 财务机器人的真实工作流

> 创建时间：2026-05-25

## 一句话总结

大模型不是从头吃到尾，是夹在中间的**阅读理解层**。95%正常数据自动跑，5%异常弹出来让人处理。

---

## 两条路

### 路一：结构化数据（发票、银行回单、报销单）

不需要大模型，传统 **OCR + 规则引擎** 就够了：

```
手机拍照发票
  → OCR识别（图片变文字：发票号、金额、税号）
  → 自动验真（对接税务局接口查真伪）
  → 自动入账（根据规则：哪个科目、哪个成本中心）
  → 人只看异常弹窗（重复报销、抬头不对、金额超标）
```

### 路二：非结构化数据（合同、邮件、聊天记录）

这才是**大模型真正发力**的地方：

```
PDF合同 / 邮件 / 微信截图
  → 扔给大模型（Claude / GPT）
  → 大模型阅读理解：付款条件？账期多久？有没有罚款条款？
  → 自动提取关键字段 → 写入财务系统
```

---

## 完整链路

```
拍照/扫描 → OCR/大模型识别提取 → 规则引擎分类校验 → 财务系统自动入账
                                    ↓
                              异常推给人处理（人点"通过"）
```

---

## 关键认知

- **大模型不是万能的**：结构化数据用OCR+规则就够了，杀鸡不用牛刀
- **人只在5%异常环节介入**：剩下的95%机器自动跑
- **签字坐牢还是人**：AI算错了，坐牢的是财务负责人，不是OpenAI
- **我的方向**：不是跟AI比谁算得快，而是能指挥AI干活 + 能看懂AI有没有出错

---

## 实际案例

- **赛力斯**：财务智能体覆盖收款上账、银行对账、发票查验等90%场景，原来每月80小时的工作10小时搞定
- **Anthropic**：发布了Claude的Excel/Word/PPT插件，直接把文件拖进去就能分析
- **OpenAI × PwC**：联合开发CFO团队AI代理，覆盖计划、预测、报告、采购、税务全流程

# 大模型对话的token管理

> 创建时间：2026-05-27

## 核心认知

每次对话不是免费的。系统提示词（CLAUDE.md + Skills + MCP + 记忆）每轮都烧token，DeepSeek API 不支持缓存，所以轮数越多越贵。

## token都烧在哪

| 消耗源 | 优化前 | 优化后 | 节省 |
|--------|--------|--------|------|
| CLAUDE.md | 6,600 tok | 1,925 tok | -71% |
| Skills描述 | ~18,000 tok | ~1,350 tok | -92% |
| MCP工具 | ~3,000 tok | ~3,000 tok | 稳定 |
| 记忆系统 | ~4,500 tok | ~400 tok | -91% |
| **系统提示词合计** | **~35,000 tok** | **~7,000 tok** | **-80%** |

## 优化手段（已验证）

1. **全局+项目CLAUDE.md去重**：个人设定放全局，项目特有的放项目文件
2. **Skill精简**：删掉重叠和用不上的，每个Skill描述只占200-500 tok
3. **记忆系统去重**：CLAUDE.md已有的规则不用再存memory
4. **大Skill拆掉**：gstack一个占了13,000 tok，删一个顶删十个
5. **Token Savior MCP**：压缩输出，省80%输出token

## 什么时候要警惕

- 一次让AI干超过3件事 → token加速燃烧
- 让AI读大文件（PDF全文、长网页）→ 输入token暴增
- 用视觉翻译桥 → 每次约2,000 tok（一张图）
- 一轮对话超过50轮 → 上下文逐渐挤满

## 实用规则

**低成本高回报**：公开API拿元数据 → 按需深入
**批量优先合并**：能一次说完的不要拆多轮
**截图按需用**：视觉翻译桥只在需要识别文字/界面时用，不要每张图都传

## 技术链路（原型版）

```
SQLite olist.db
  → Python 跑 SQL（昨日 GMV、运费、毛利、Top5）
  → matplotlib 画 3 张图（销售趋势、品类占比、运费变化）
  → 拼 HTML 邮件正文（表格 + 图片直接嵌进去）
  → SMTP 发到 QQ 邮箱
  → 手机弹窗
```

## 公司数据库的真实限制

> 不是说"换个数据库就行"那么简单。

| 限制 | 什么意思 | 影响 |
|------|----------|------|
| **网络隔离** | 数据库在阿里云/华为云内网，要 VPN 或公司专线才能连 | 在家连不上 |
| **权限管控** | 每人只给读权限，能看什么表、什么字段都是定的 | 不是想看什么就看什么 |
| **只给 API，不给数据库** | 亚马逊 SP-API 是 REST 接口，不是 SQL 直连 | 你得调接口取数据，再自己存 |
| **ERP/中台拦截** | 公司接易仓、马帮等 ERP，所有数据走中台，底层库不让你碰 | 你能用的只有 ERP 导出的 CSV |
| **审计日志** | 你查了什么、什么时候查的，全记录，出事能追溯 | 不能乱跑查询 |

### 真实数据流

```
亚马逊 SP-API / ERP导出CSV      ← 你控制不了
         │
         ▼
你自己搭的本地分析库（SQLite）    ← 你控制的，SQL 脚本在这儿跑
         │
         ▼
    Python → SQL → 报表          ← 你的代码
```

**我之前说的"换数据库"，指的是中间那层本地分析库——数据来源换了，你的 SQL 和报表模板不变。**

## 接入真数据时要改什么

| 组件 | 现在 | 大叔店铺（有 ERP） | 正式入职后 |
|------|------|-------------------|-----------|
| 数据来源 | Olist CSV 下载 | ERP 导出的 CSV/Excel | SP-API 或 ERP 定时导出 |
| 存储 | SQLite `olist.db` | SQLite 本地分析库 | SQLite/MySQL 本地分析库 |
| 数据清洗 | Power Query 9 表合并 | 按 ERP 格式重写清洗脚本 | 可能用 Python 替代 Power Query |
| SQL 字段 | Olist 9 表结构 | 大叔的表结构（重新写 SQL） | 按公司口径调整 |
| 触达渠道 | QQ 邮箱 | QQ 邮箱 / 微信 | 飞书机器人 / 企业微信 |

**Python 脚本框架不变（读库 → 跑 SQL → 画图 → 发邮件），变的是数据来源和 SQL 查询。**

## SQL vs RAG：什么时候用哪个

> 不是所有数据都走数据库。分两类。

| | 结构化数据 | 非结构化数据 |
|------|-----------|-------------|
| 是什么 | 订单表、金额、日期、运费 | PDF 合同、邮件、聊天记录、政策文件 |
| 怎么查 | `SELECT SUM(price) WHERE date='...'` | "帮我翻合同，找交货延期超 3 天的条款" |
| 用什么工具 | SQL | RAG（让 AI 先读一堆文档，再回答） |
| 日报用得到吗 | **用得到，核心指标全靠 SQL** | 用不到 |

### 具体例子

```
结构化 → SQL 直接算
"昨天卖了多少钱？" → SELECT 就行，不需要 AI

非结构化 → RAG 检索
"我们跟供应商签的 2025 年账期是多少天？" 
→ 合同是 PDF，散落在文件夹里
→ RAG 先翻 20 份合同 PDF，找到跟这个供应商有关的那份
→ 再提取账期条款
→ 最后回答你
```

**日报场景 90% 是结构化数据，SQL 就够了，不需要 RAG。**

RAG 的用武之地是另一类事：合同审核、政策检索、客服话术分析。那是大三/实习阶段会碰到的。

## 附：MCP 和 RAG 的区别

| | MCP | RAG |
|------|-----|-----|
| 比喻 | 万能插头，不同系统统一接到 AI | 智能翻书，先搜后答 |
| 干什么 | 让 AI 能操作数据库、发邮件、调 API | 让 AI 能读懂一堆文档再回答问题 |
| 日报场景 | 定时任务 + SMTP 走 Python，不需要 MCP | 不需要，日报是数字计算不是文档翻查 |
